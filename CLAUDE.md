# CLAUDE.md

Контекст проекта для Claude Code. Читать перед любой правкой.

## Что это

`zotov.by` — личная страничка Сергея Зотова, шуточная стилизация под домашние сайты
русского интернета 1999 года. Сервер современный (Node + TypeScript + Hono), а HTML,
который он отдаёт, намеренно архаичный.

**Главное правило: старомодность — это фича, а не долг.** Фреймы, `<font>`, вёрстка
таблицами, `<marquee>`, `bgcolor` в атрибутах, гифки под «строительство» — так задумано.
Не модернизировать, не «чинить» и не предлагать рефакторинг в эту сторону, пока
пользователь не попросит прямо.

## Стек и запуск

Node 20+ (в CI — 20, локально 22 тоже работает), ESM, TypeScript strict.
Hono + `@hono/node-server`, шаблоны — тегированные строки `hono/html`, база — `pg`.

```sh
npm run dev        # tsc --watch + node --watch
npm run typecheck  # единственная проверка перед деплоем, тестов и линтера нет
```

Проверять работу правок: `npm run typecheck`, дальше глазами на `localhost:3000`.

## Архитектура

```
src/server.ts     маршруты, парсинг форм, валидация, антиспам. Одно место на все роуты
src/layout.ts     SITE (имя, ник, дата обновления, ссылки) + примитивы вёрстки:
                  contentPage / heading / panel / divider / cautionLine / footer
src/db.ts         интерфейс Store; MemoryStore (без базы) и PostgresStore
src/pages/*.ts    по файлу на страницу; экспортирует одну функцию, возвращающую Html
public/           статика: img/, music/, cursor.js, favicon, robots.txt, sitemap.xml
```

Страница ничего не знает про Hono и про базу: получает готовые данные аргументами
(`homePage(hits)`, `votePage(tally, hasVoted)`) и возвращает `Html`. Всю работу с
запросом делает `server.ts`.

Импорты внутри `src/` — с расширением `.js` (ESM после компиляции): `from "../layout.js"`.

## Правила вёрстки

Всё это — сознательно, повторять при добавлении нового:

- Доктайп `HTML 4.01 Transitional` (у `/main` — `Frameset`).
- Раскладка таблицами: `<table border="0" cellpadding cellspacing>`, `<center>`, `align`,
  `valign`, `width="90%"`. Никакого flexbox и grid.
- Цвета и шрифты — атрибутами: `bgcolor`, `text`, `link`, `vlink`, `alink`,
  `<font face="Arial" size="2" color="#FFFF99">`. **CSS-файлов в проекте нет и быть не
  должно**; инлайновый `style` допустим только там, где иначе никак (позиционирование
  звёздочек в `cursor.js`, скрытая honeypot-строка формы).
- У каждой картинки — `width`, `height`, `alt`, `border="0"`.
- JavaScript на страницах — в стиле эпохи: `var`, функции верхнего уровня,
  `window.setTimeout`, обёртка `<script language="JavaScript" type="text/javascript">`
  и комментарий `<!-- ... // -->`. Никаких `const`, стрелок и модулей во фронтенде.
- Тексты — по-русски, к посетителю на «Вы», с восклицательными знаками и обещаниями
  «скоро обновлю». Тон держать: он и есть содержание сайта.

Осознанные отступления от 1999 года — их не «исправлять обратно»:

- Музыка отдаётся как `theme.mp3` через `<audio>`: MIDI и `<embed>` современные браузеры
  не играют. `theme.mid` лежит рядом как исходник.
- В `menu.ts` есть обработка блокировки автоплея — без неё музыка молча не запускается.
- Внешние ссылки на мёртвые сайты ведут в web.archive.org.

## Безопасность и данные

- Тегированные строки `hono/html` экранируют подстановки автоматически.
  **`raw()` — только для статических строк** (`STATUS_TICKER`, скрипт музыки).
  Никогда не оборачивать в `raw()` то, что пришло от посетителя.
- Ссылка «домашняя страничка» в гостевой книге проходит через `safeHomepage()`:
  пускаем только `http:`/`https:`, иначе в `href` протащат `javascript:`.
- Антиспам гостевой книги: honeypot-поле `homepage_url` + 30 секунд между записями
  с одного IP (`lastPostAt`, живёт в памяти процесса). Лимиты длины — на сервере.
- Голосовалка защищена только cookie `voted`. Это шутка, а не защита; так и задумано.

## База

Схема задаётся `DB_SCHEMA` (по умолчанию `zotovby`). **База на проде общая с чужим
проектом — в схему `public` не писать никогда.** Имя схемы подставляется в SQL строкой,
поэтому `resolveSchema()` пропускает только `[a-z_][a-z0-9_]*` — валидацию не ослаблять.

Миграций нет: таблицы (`counter`, `guestbook`, `votes`) создаются в `PostgresStore.init()`
через `CREATE TABLE IF NOT EXISTS`. Новое поле — это правка `init()` плюс, если таблица
уже существует на проде, отдельный `ALTER TABLE`; `CREATE TABLE IF NOT EXISTS` его
не добавит.

Без `DATABASE_URL` поднимается `MemoryStore` — рабочий режим для локальной разработки.
Любой новый метод `Store` нужно реализовать в обеих реализациях.

## Деплой

Пуш в `master` → `.github/workflows/deploy.yml` → `npm ci`, `npm run typecheck`,
`railway up --ci --service zotov-by`. Сборку делает Railway (Railpack), в CI уезжают
только исходники.

Railway: личный workspace `s.zotov`, проект `nohable`, сервис `zotov-by`, environment
`production`. Домен привязан к target port 3000, поэтому на сервисе явно задан `PORT=3000`.
Перед любой railway-командой в этом репозитории — проверить `railway status`: папка
когда-то была слинкована с рабочим проектом, легко залить не туда.

## Чек-лист: новая страница

1. `src/pages/<name>.ts` — одна экспортируемая функция, возвращает `contentPage(title, body)`.
2. Роут в `src/server.ts` рядом с остальными `app.get(...)`.
3. Пункт в `ITEMS` в `src/pages/menu.ts` (при желании с `isNew: true` и гифкой `new.gif`).
4. `<url>` в `public/sitemap.xml`.
5. Строка в таблице страниц в `README.md`.
6. Если раздел заметный — запись в блок «Что нового» на `/home` и свежая дата
   в `SITE.updated` (`src/layout.ts`).

## Чего не делать

- Не добавлять CSS-файлы, сборщики, React/Tailwind и прочий современный фронтенд.
- Не убирать фреймы, `<marquee>`, счётчик, бегущую строку в статусбаре и звёздочки за
  курсором — это и есть сайт.
- Не приводить разметку к HTML5 и не гнаться за валидностью ради валидности.
- Не использовать `any` в TypeScript.
- Не заменять картинки на SVG или иконочные шрифты: только гифки из `public/img/`.
